# AI EDA ENGINEER — project notes for Claude

Verification-first AI circuit design system. **The LLM never decides design truth.** The Universal Circuit IR (`ai_eda/ir/`) is the only original design data; every important value is `Traced[T]` with provenance; correctness claims come only from deterministic tools (calculators, SPICE, `kicad-cli` ERC/DRC, manufacturing checks) and the independent reviewer. Read `docs/ARCHITECTURE.md` for the invariants and the spec↔module map.

## Invariants (do not break)
1. Derived artifacts (`.kicad_sch`, `.kicad_pcb`, `.kicad_pro`, BOM, CPL, netlists, gerbers) are compiled from the IR and registered as `ArtifactRef` with `generated_from_ir_hash`. `<workdir>/report.html` and `<workdir>/pipeline.json` are not artifacts: they describe the validation log, so they are never registered in `ir.artifacts` and never hashed. Compilers must be deterministic: same IR → byte-identical output (use `ai_eda.compilers.ids.stable_uuid`, never `uuid4()`/time). The design hash is the *design view* (`CircuitIR.design_dict`): a model drops its own wall-clock, locator (`document_path`, `library_path`, `source_document`) and verification-outcome fields with `drop_in_design_view`; never strip by key name.
2. A compiler never emits a symbol/footprint it did not find on disk in a KiCad library (`ai_eda.tools.kicad.library`). Pin numbers / pad geometry come from the library file, never from model memory. Mismatch between IR pins and library pins is an error, not a guess.
3. `ValidationStatus` is never boolean. No evidence → `NOT_VERIFIED`, never `PASS`. ERC/DRC results are produced only by `ai_eda/tools/kicad/cli.py`. `mfg.capability` is produced only by `ai_eda.tools.manufacturing.capability.check_capability` and can PASS only on DRC evidence that read the fresh `.kicad_pro` on a kicad-cli version in `PROJECT_RULES_MEASURED_VERSIONS` (empty until measured, so it cannot PASS anywhere yet); fab limits enter the IR only through `--fab-capability` grounding (`ai_eda/tools/manufacturing/capability_file.py`) or the user. `component.fit` and `domain.power.thermal` judge only at a fresh SPICE operating point and answer `NOT_VERIFIED` with the reason for everything they cannot judge (never a proxy verdict); the thermal check applies to every design — no component with a thermal key means `NOT_VERIFIED` naming the keys in the POWER domain and `NOT_APPLICABLE` elsewhere.
4. Agents return `IRProposal`s; only `Orchestrator.apply_proposals` mutates design content, and it validates every payload against the target field's type (`ir.artifacts` / `ir.validation` bookkeeping is written by the stage runners). A required question stops the pipeline even when a FAIL in the same stage outranks it. The pipeline has 19 stages (`STAGE_ORDER` in `ai_eda/workflow/stages.py`): PLACEMENT (`PCBAgent`, deterministic grid placement then `routing.maze` routing in one `pcb` proposal, never PASS — a proposal is not evidence; `--answer pcb.placement=skip` skips the stage, `--answer pcb.routing=skip` leaves the placement without copper; a net the router cannot route means placement only, never a half-routed board, and existing copper is never replaced; `pcb.routing.connectivity` / `pcb.routing.clearance` in `ai_eda/validation/layout.py` are IR geometry checks, never DRC) and FAB_CAPABILITY (`FabCapabilityAgent`, grounded fab limits merged into `pcb.manufacturing`) sit between COMPONENT_SELECTION and IR_BUILD, so validators stamp the placed IR. `CircuitDesignAgent` proposes only from deterministic templates on confirmed requirement values and applies nothing on the run that first shows the `confirm_design` table: a template's free choices become `user_requirement` only through `--answer confirm_design=yes` on a later run whose answers cannot change the inputs (no non-control answer, no `confirm_requirements` / `accept_implicit` / `reject_implicit`) and whose table hash equals the one recorded when it was shown (`ir.requirements.presented`, bookkeeping outside the design hash). `design.inputs_vs_requirements` is an unstamped agent result. Every control key (`confirm_design`, `pcb.placement`, ...) lives in one `CONTROL_KEYS` in `ai_eda/agents/keys.py`; a control answer is never a requirement or a regulatory scope answer.
5. Repairs only regenerate artifacts from the IR or re-run tools. Design changes need a human.
6. Outward-facing actions go through `ai_eda.security.require_approval`.

## Conventions
- Python 3.12, pydantic v2, `from __future__ import annotations`, type hints everywhere, small modules, docstrings that state the invariant the module enforces.
- Tests in `tests/`; tests that need `kicad-cli` use `pytest.mark.skipif(not KicadCli().available(), ...)` and must otherwise run against the real binary.
- Tool-backed `ValidationResult`s set `tool`, `tool_version`, `artifact_hash`, and attach `Evidence` (report path + hash). A validator that judges by the SPICE operating point reads it only through `ai_eda.tools.spice.evidence.fresh_spice_run` (never `ir.artifacts` directly) and keeps every derived number in `details`, never in the IR.
- `<workdir>/pipeline.json` (written by `ai-eda run`, read by `ai-eda report` / `serve`) is a run log like `ir.validation`: never registered as an artifact, never hashed; the report is English, computes no status and never saves the IR; `serve` binds 127.0.0.1 only (no `--host`) and is not an `ExternalAction`.
- BOM free-text cells (`Value` / `Description`) are neutralised with a leading apostrophe by `ai_eda/tools/manufacturing/csv_cells.py` (`free_text_cell`, decoded only by `bom_cell_text`); identity / sourcing cells and CPL designators are refused instead. Whether spreadsheets show the apostrophe literally is not measured here.
