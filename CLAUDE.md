# AI EDA ENGINEER — project notes for Claude

Verification-first AI circuit design system. **The LLM never decides design truth.** The Universal Circuit IR (`ai_eda/ir/`) is the only original design data; every important value is `Traced[T]` with provenance; correctness claims come only from deterministic tools (calculators, SPICE, `kicad-cli` ERC/DRC, manufacturing checks) and the independent reviewer. Read `docs/ARCHITECTURE.md` for the invariants and the spec↔module map.

## Invariants (do not break)
1. Derived artifacts (`.kicad_sch`, `.kicad_pcb`, `.kicad_pro`, BOM, CPL, netlists, gerbers, the built-in 3D preview `<project>.preview.glb` - `ArtifactKind.MODEL_3D`, `compilers/model3d.py`, compiled in the PCB stage right after the board, a picture that records no status - and kicad-cli's own STEP / GLB / render exports under `<workdir>/3d/`, registered like the gerbers: KiCad writes its own timestamps into them, so their hash says which file, not reproducibility) are compiled from the IR and registered as `ArtifactRef` with `generated_from_ir_hash`. `<workdir>/report.html`, `<workdir>/pipeline.json` and the Korean stage reports `<workdir>/reports/*.{md,html,pdf}` are not artifacts: they describe the validation log, so they are never registered in `ir.artifacts` and never hashed (the `.md` / `.html` are deterministic views; the `.pdf` bytes carry the browser's own creation date - a derived document like a rawfile, not deterministic). Compilers must be deterministic: same IR → byte-identical output (use `ai_eda.compilers.ids.stable_uuid`, never `uuid4()`/time). The design hash is the *design view* (`CircuitIR.design_dict`): a model drops its own wall-clock, locator (`document_path`, `library_path`, `source_document`) and verification-outcome fields with `drop_in_design_view`; never strip by key name. A design field added after IRs were saved (`PCBDesign.silkscreen`, `ManufacturingConstraints.min_silk_text_height_mm` / `min_silk_line_width_mm`, `PCBDesign.stackup`, `CircuitIR.si`, `Expectation.params` / `reference_vector`, `NetClass.rf_frequency_hz`, `SIConstraints.rf_length_fraction` - those four pinned by `tests/data/ir_before_rf.json` -, `CircuitIR.rf`, `Expectation.bound`, `PCBDesign.keepouts` - pinned by `tests/data/ir_before_kr447.json`; each fixture saved and hashed by the code before its fields existed) is left out of the design view only while empty (`drop_empty_in_design_view`), so every older IR keeps its hash. A project writes only into the folder that holds its ir.json (`ai_eda/workdir.py`): a recorded absolute `project.workdir` naming another folder (a copied or moved project; also a path absolute only under the other OS's rules, `C:\...` read on Linux) is refused by `run` / `review` / `report` / `serve` / `stage-reports` (exit 2 naming both paths and the remedy; nothing run, read from or created in either folder), never followed; so is an IR whose registered artifacts (`ArtifactRef.path` / `files`, always compiled into the workdir) lie by absolute path outside the ir.json's folder, whatever its workdir says (none, a relative one the copy's tail still matches, this folder: `workdir.stray_artifacts`); `ai-eda relocate <ir.json> [--from OLD]` alone re-records it, rebasing the `ArtifactRef` / `Evidence` / `document_path` / `library_path` / `source_document` paths under the old folder - the recorded absolute workdir, else the folder the artifacts show (`infer_old_folder`: a relative workdir's matching ancestor, the root-level artifacts' folder), else `--from` - (other paths, `details` and messages untouched), dropping the `SPICE_RESULT` reference (results.json names its rawfiles by absolute path; the next run re-simulates) and refusing (exit 2, nothing written) when it cannot tell the old folder or an artifact would stay outside - every field it touches is outside the design view and it compares the hash before saving; `new --dir <a file>` says the path is not a folder (only an existing ir.json is 'already exists'). The per-project lock `<workdir>/.ai-eda.lock` is not an artifact either: never registered, hashed, zipped or deleted.
2. A compiler never emits a symbol/footprint it did not find on disk in a KiCad library (`ai_eda.tools.kicad.library`). Pin numbers / pad geometry come from the library file, never from model memory. Mismatch between IR pins and library pins is an error, not a guess.
3. `ValidationStatus` is never boolean. No evidence → `NOT_VERIFIED`, never `PASS`. ERC/DRC results are produced only by `ai_eda/tools/kicad/cli.py`. `mfg.capability` is produced only by `ai_eda.tools.manufacturing.capability.check_capability` and can PASS only on DRC evidence that read the fresh `.kicad_pro` on a kicad-cli version in `PROJECT_RULES_MEASURED_VERSIONS` (empty until measured, so it cannot PASS anywhere yet); fab limits enter the IR only through `--fab-capability` grounding (`ai_eda/tools/manufacturing/capability_file.py`) or the user. `component.fit` and `domain.power.thermal` judge only at a fresh SPICE operating point and answer `NOT_VERIFIED` with the reason for everything they cannot judge (never a proxy verdict); the thermal check applies to every design — no component with a thermal key means `NOT_VERIFIED` naming the keys in the POWER domain and `NOT_APPLICABLE` elsewhere. Signal integrity is need-driven (`ir.si` net classes / timing paths, `ir.pcb.stackup`; every number a registered calculator's output - `calc.tline.*` -, a grounded fact or a confirmed choice): `si.*` (`ai_eda/validation/si.py`, only when `ir.si` is set) are IR-geometry + calculator checks, never DRC (`si.width` makes a member net with two or more pads and no track a NOT_VERIFIED row - `details["unrouted"]` -, NOT_APPLICABLE only when no member needs copper); `spice.si.<net>` (`ai_eda/tools/spice/si_check.py`, the SPICE stage) is ngspice evidence (deck + rawfile, a stem unique per exact net name) for each electrically long net over a plane that *is* the deck's circuit - one driver, one line, one receiver: a net with more than two pads, a pad of a part the deck does not model (a resistor, capacitor, switch, crystal ...) or a class driver whose pin there is only an input is `NOT_VERIFIED` naming it, never a verdict about a circuit not in the IR; the critical-length rule measures a net's *line* - its longest pad-to-pad path (`tools/si/paths.py`, from the copper and the library's pad boxes), or a 2-pad net's copper - never the summed branches, which are only an upper bound (a net whose total exceeds l_crit without an extracted path is "possibly long": `NOT_VERIFIED`, never promoted); a driver's grounded datasheet edge applies only on nets it drives (an output / bidirectional pin there); no stackup ("no stackup"), no reference plane ("impedance is undefined without a reference plane - use pcb_layers=4 or add a plane", said only for copper on a layer the stack gives no plane; copper under a keep-out that forbids its plane's zone - a polygon by its bounding box - has no plane either, and `spice.si` / `si.critical_length` / `si.rf_length` / `si.impedance` name that keep-out instead (`tools/si/measure.py` `plane_keepout` / `no_plane_reason`); a delay without a plane is only the upper bound sqrt(er)/c0 - under a keep-out sqrt(er_max)/c0 of the whole stack -, used only in the direction it holds) or an ungrounded datasheet timing term (named) is `NOT_VERIFIED`, never a number made up. A fab's `stackup` block (`--fab-capability`) is grounded and reported but not written into `ir.pcb.stackup` in this version (`mfg.capability_source` says "not recorded in the IR"), and the compiled `.kicad_pcb` carries no `(stackup)` section: KiCad shows its own default stack, not `ir.pcb.stackup`. RF is marked by the IR only (`NetKind.RF`, or a class's `rf_frequency_hz`; `ai_eda/tools/si/rf.py`) and its frequency is the class's, else the confirmed `carrier_frequency` requirement (ambiguous / unconfirmed = no frequency): `si.rf_length` (only with RF nets) measures the same line / t_pd / bound flag as the critical-length rule against `rf_length_fraction` (a confirmed choice, never defaulted) x lambda_g - short PASS, long over a plane handed to `si.impedance` / `domain.rf.impedance` (NOT_APPLICABLE row) when the class has a target Z0 else "needs impedance control" NOT_VERIFIED, long only by a bound "possibly long" NOT_VERIFIED; it never promotes or re-routes. `domain.rf.impedance` (`RFImpedanceValidator`) is selected only for a design that carries RF (RF nets or the RF domain) and judges `si.impedance` per class holding RF nets on the RF member nets' rows only (a class shared with non-RF nets never lends their PASS to RF copper nobody judged, nor their FAIL to the RF verdict - they are `other_members` context and stay in `si.impedance.<class>`): PASS only through PASSing rows of RF nets, RF rows that are all NOT_APPLICABLE (every segment a neck-down, or fewer than two pads) are NOT_VERIFIED naming each, unrouted RF copper is NOT_VERIFIED, no `ir.si` / target / plane / placed board is NOT_VERIFIED naming it; matching networks, S-parameters and the antenna are named as not judged. `spice.rf.<network>[.<state>].<exp>` + a `spice.rf.<network>` summary (`ai_eda/tools/spice/rf_fixture.py`, the SPICE stage after `spice.si`) simulate one deck per (network, state, drive port) of `ir.rf.networks` holding only the members (binding: state > network fixture binding > `Component.spice`; an excluded member without a fixture binding is refused) and four added element kinds (the drive's ac 1 V behind z0; z0 loads at the other ports, ideal DC sources at rail / control ports; the `loss_q` series R = 2 pi f L / Q; 1e12 ohm DC paths - R / L / V / D / Q, M drain / source / bulk and T conductors conduct, C / I / X do not), compiled by `compilers/spice.build`; S21 = 2 V_to / V_s sqrt(R_drive / R_to), S11 = 2 V_drive / V_s - 1 (to a probe only phase and relative level); a row is read only at an exact sample of its own `ac lin 1 f f` point analysis (`rf_at_<k>`, within 1e-12 relative), never between sweep points; an exact zero |S| is -inf dB (PASS on an `at_most` bound, FAIL on `at_least` / `tol_abs`); a PASS is "a network verdict under the confirmed model values" (schematic level, no track or ground-return inductance), an assumption makes it NOT_VERIFIED, a malformed network FAILs its summary and a malformed row itself, no engine is NOT_VERIFIED. A one-sided `Expectation.bound` (`at_least` / `at_most`) replaces the tolerance: PASS only when the whole interpolation / bias bracket is on the passing side of nominal (equal passes), FAIL only when all of it fails, UNRESOLVED when it straddles (`details["bound"]`, tolerance None, the signed deviation); the compiler refuses a bound with `tol_abs` / `tol_rel` or a `requirement_id`, a bound waives the dB `tol_abs` rule, `judge` also judges `RFExpectation`, and the SPICE stage never retires `spice.rf.*` (`RF_CHECK_PREFIX`; the runner supersedes its own). The RF checks (`ai_eda/validation/rf.py`, tool `rf.checks`, only with `ir.rf`, again after SPICE) are IR arithmetic, registered calculators called by role and SPICE verdicts already recorded - used only when tool-backed and stamped with the current design hash and, where a measured number is taken, with every evidence file matching its hash: `rf.regulatory_profile` (the unverified `kr447.*` placeholders; a confirmed exceedance is FAIL) and `rf.lab.<id>` never PASS; a confirmed choice is not grounded, so `rf.model_grounding` and `power.*` PASS only on authoritative values with a source (every wave-1 `model.*` value is an UNVERIFIED choice: `rf.model_grounding` is NOT_VERIFIED) and `power.*` FAILs only when confirmed values contradict each other; `rf.deviation` is PASS / FAIL only when every factor PASSed on this design (its `bias_lo` / `bias_hi` pair shares drive, port read and frequency); ids the IR no longer produces get a superseding NOT_APPLICABLE. The level / window reductions (`db_at`, `rms`, `db_rms`, `harmonic_dbc`, `am_depth` in percent; `ai_eda/tools/spice/measure.py`) never PASS without a number: a grid coarser than their guard (1 / (20 f_max) for `rms` / `db_rms` - `params["f_max"]`, the highest frequency the RMS must include, is required -, 1 / (20 k f0) for a harmonic, 1 / (16 f_carrier) per carrier period for AM depth), a zero reference, no fundamental, a harmonic window whose samples do not repeat at `f0` (fewer than 2 periods, or a periodicity residual RMS(v(t + 1/f0) - v(t)) above 2 % of the fundamental: its own fundamental is another frequency - the rising edges' frequency is named -, a start-up, a modulation) or a window outside the saved samples is FAIL (human) with the reason, and a harmonic at or below the engine's resolution floor is NOT_VERIFIED ("not resolved"), never PASS; `rms` / `db_rms` / `harmonic_dbc` / `am_depth` are judged on the bracket their bias bounds leave (the RMS read-low bound at `f_max`, the harmonic's grid attenuation and leakage bound, the AM crest / envelope bounds; `details["bias_bracket"]`) like `at`: PASS only when all of it is inside, FAIL only when all of it is outside on one side, UNRESOLVED otherwise; a dB level needs `tol_abs` and no `tol_rel`.
4. Agents return `IRProposal`s; only `Orchestrator.apply_proposals` mutates design content, and it validates every payload against the target field's type (`ir.artifacts` / `ir.validation` bookkeeping is written by the stage runners). A required question stops the pipeline even when a FAIL in the same stage outranks it. The pipeline has 19 stages (`STAGE_ORDER` in `ai_eda/workflow/stages.py`): PLACEMENT (`PCBAgent`, deterministic placement - `placement.rf_floorplan` when the IR has RF blocks (`ir.rf.blocks`: block regions, chain order, shield cans first with their block's parts inside the fence; it refuses rather than overlaps, and a shielded block without a region is a `CompileError`), else `placement.core_ring` when a part has at least 32 pads, `placement.grid` otherwise - then `routing.maze` 0.2 routing at the rules the finest pad pitch selects (`RoutingParams.for_board`: below 1.0 mm the fine rules), then `silkscreen.place` silkscreen (references beside their courtyards, on F.Fab when no spot is free; connector pin labels; the ASCII project name as title; keep-outs are pad copper, the board edge, the footprints' own silk and earlier texts - not tracks, not the tented vias), all in one `pcb` proposal, never PASS — a proposal is not evidence; with `ir.si` the router gets the net-class rules (`tools/si/rules.py` → `routing.maze` 0.3 `NetRule`: controlled width from `calc.tline.width_for_z0` over the plane, neck-down, length budgets, meanders, coupled pairs only where a class declares them; a board without rules is 0.2's copper byte for byte - a board-level fact: once any net has a rule every net is negotiated together, stamped 0.3, and may take another path than 0.2; a budgeted net whose reroute fails at one iteration's costs keeps its earlier route; a meander never lies on or against the net's own copper; a pair's `pair_uncoupled_max_mm` bounds each net's uncoupled copper - breakouts, mitred corners, bumps - exactly as `si.diff` measures it, `tools/routing/coupling.py`), then every net's line delay is measured and each electrically long net (line delay > fraction x t_r) of a class with `promote_to` is promoted (a second `si` proposal, `derived` / `si.promote`) and the board re-routed **once** (a re-route that loses a net keeps the first pass; `si.impedance` then judges the promoted nets at the width they have - a narrower track is a neck-down only where the router recorded one near the net's pads), a 4-layer board gets its plane zones, then the silkscreen; a board with keep-outs (`ir.pcb.keepouts`) or RF blocks hands the router its keep-outs and plane nets, and copper routed with either is `routing.maze` 0.4 (keep-outs are obstacles except for their allowed nets - a track keep-out lets only a single allowed net through; each SMD pad of a plane net gets one via inside its plane zone - never tracks between pads, a through-hole pad reaches by its barrel, an SMD pad under a same-number same-net through-hole pad of its footprint by those vias -, and a plane net with a pad no via site reaches is unrouted whole; the plane zones are clipped by zone-forbidding keep-outs), a board with a KiCad `custom` pad is `routing.maze` 0.5 (`ROUTER_CUSTOM_PAD_VERSION` whatever else it has, `derived_from` `custom_pads:...;model=anchor+primitive_boxes`: the pad's copper is `tools/kicad/geometry.custom_pad_parts` - the anchor's box plus one box per copper primitive grown by half its stroke, an outer bound and the one extent the router, the layout checks, the silkscreen, the SI paths, the 3D scene and the figures read -, a track lands on the anchor, else on a part known to be copper; a trapezoid or a pad with a primitive the reader did not read is still refused), every other board keeps 0.2 / 0.3 / 0.4 byte for byte (compared on the divider, led, rc_lowpass, astable, ATmega128 2- / 4-layer and rx_backend boards); the router negotiates congestion (PathFinder-style rip-up and reroute: other nets' clearance halos are a present + history cost, not an obstacle, until no cell is shared or `max_iterations`; every negotiation number is a `RoutingParams` field in each track's `params:` provenance, the note names the iteration count) and emits only whole, mutually legal nets - a net without a legal route gets no copper at all, never half a net; `--answer pcb.placement=skip` skips the stage, `--answer pcb.routing=skip` leaves the placement without copper, `--answer pcb.silkscreen=skip` proposes no silkscreen; by default a net the router cannot route means placement only (a `not applied:` note reports what it did connect), and only the opt-in `--answer pcb.routing=partial` applies the routed nets, each whole, naming every unrouted net for manual routing in KiCad (`pcb.routing.connectivity` then FAILs naming them); existing copper and existing silkscreen are never replaced; `pcb.routing.connectivity` / `pcb.routing.clearance`, `pcb.keepout` and `pcb.silk.clearance` / `pcb.silk.overlap` / `pcb.silk.size` in `ai_eda/validation/layout.py` are IR geometry checks, never DRC (a net joined only through a plane is NOT_VERIFIED, an SMD pad no pour reaches FAILs; KiCad's rule areas do not know a keep-out's exemptions, only `pcb.keepout` does; connectivity is judged per net: a net holding a pad whose copper is unknown - a trapezoid, an unread primitive or footprint - is a NOT_VERIFIED row naming it, every other open net still FAILs, and the check never PASSes while such a net remains; clearance is NOT_APPLICABLE without IR copper and NOT_VERIFIED with unknown pads unless it finds a violation; a custom pad's box or disc that only bounds its copper - a ring, a line's box - never makes a FAIL: copper or silk meeting only that bound is NOT_VERIFIED (`bounded_pads`, `details["custom_pad_bounds"]`, `PadCopper.bound`), copper clear of a part's `PadPart.disc` by the limit is clear, and `pcb.keepout` FAILs only on known copper) - the silk text boxes are a documented estimate, not KiCad's font metrics) and FAB_CAPABILITY (`FabCapabilityAgent`, grounded fab limits merged into `pcb.manufacturing`) sit between COMPONENT_SELECTION and IR_BUILD, so validators stamp the placed IR. `CircuitDesignAgent` proposes only from deterministic templates (`divider`, `led`, `rc_lowpass`, `astable`, `atmega128_devboard`; the radio family `ai_eda.design.rf.registry.RF_TEMPLATES`, imported lazily through `all_templates()`, holds the five kr447 templates since wave 2 (`kr447_audio_ptt`, `kr447_rx_backend`, `kr447_rx_frontend`, `kr447_tx_exciter`, `kr447_transceiver` with its `transceiver_conducted` build) - each is selected by the categorical requirement `radio_build` through `Template.triggered_by`, and a confirmed `carrier_frequency` / `modulation` without it is the family's required question; `Template.layer_policy` (`LayerPolicy`, default 2|4 with 2; the four RF kr447 templates 4 only, `kr447_audio_ptt` 2|4 with 4) refuses a stated layer count outside it before any missing input is asked) on confirmed requirement values and applies nothing on the run that first shows the `confirm_design` table: a template's free choices become `user_requirement` only through `--answer confirm_design=yes` on a later run whose answers cannot change the inputs (no non-control answer, no `confirm_requirements` / `accept_implicit` / `reject_implicit`) and whose table hash equals the one recorded when it was shown (`ir.requirements.presented`, bookkeeping outside the design hash). A template with validity ranges refuses a stated out-of-range input before it asks for a missing one (`rc_lowpass` 2 Hz..100 kHz - engineering bounds of the ideal unloaded RC, not measured -, `astable` 3..6 V / 100 Hz..20 kHz, `atmega128_devboard` 7..15 V / 1..16 MHz). The bare key `frequency` is no alias of anything (`design/base.py` `AMBIGUOUS_KEYS`): no template reads it, the circuit agent asks which frequency (a non-required question under that key listing the `*_frequency` keys of `UNIT_OF`), and it counts as served only beside the template's specific key stated with the same number (then the parts serving that key list it too). `missing_information` is PASS only for a user-confirmed `requirements.extraction` of the current request text; no request text, no `--llm` (only the baseline checklist) or an unconfirmed / other-text extraction is NOT_VERIFIED with the reason. `design.inputs_vs_requirements` is an unstamped agent result. Every control key (`confirm_design`, `pcb.placement`, ...) lives in one `CONTROL_KEYS` in `ai_eda/agents/keys.py`; a control answer is never a requirement or a regulatory scope answer.
5. Repairs only regenerate artifacts from the IR or re-run tools. Design changes need a human.
6. Outward-facing actions go through `ai_eda.security.require_approval` (`PAID_API_CALL`: the `--llm-budget-*` flags are the approval of per-call model charges; `SUBSCRIPTION_USE`: `--llm claude` is the approval of calling the model through the user's own Claude Code CLI login - no per-call charge, no budget required, but the run shows the tokens and the CLI's API-equivalent estimate; `NETWORK_FETCH`: `--online`; `SECRET_ACCESS`: `doctor --online`).
