# AI EDA ENGINEER — project notes for Claude

Verification-first AI circuit design system. **The LLM never decides design truth.** The Universal Circuit IR (`ai_eda/ir/`) is the only original design data; every important value is `Traced[T]` with provenance; correctness claims come only from deterministic tools (calculators, SPICE, `kicad-cli` ERC/DRC, manufacturing checks) and the independent reviewer. Read `docs/ARCHITECTURE.md` for the invariants and the spec↔module map.

## Invariants (do not break)
1. Derived artifacts (`.kicad_sch`, `.kicad_pcb`, `.kicad_pro`, BOM, CPL, netlists, gerbers, the built-in 3D preview `<project>.preview.glb` - `ArtifactKind.MODEL_3D`, `compilers/model3d.py`, compiled in the PCB stage right after the board, a picture that records no status - and kicad-cli's own STEP / GLB / render exports under `<workdir>/3d/`, registered like the gerbers: KiCad writes its own timestamps into them, so their hash says which file, not reproducibility) are compiled from the IR and registered as `ArtifactRef` with `generated_from_ir_hash`. `<workdir>/report.html`, `<workdir>/pipeline.json` and the Korean stage reports `<workdir>/reports/*.{md,html,pdf}` are not artifacts: they describe the validation log, so they are never registered in `ir.artifacts` and never hashed (the `.md` / `.html` are deterministic views; the `.pdf` bytes carry the browser's own creation date - a derived document like a rawfile, not deterministic). Compilers must be deterministic: same IR → byte-identical output (use `ai_eda.compilers.ids.stable_uuid`, never `uuid4()`/time). The design hash is the *design view* (`CircuitIR.design_dict`): a model drops its own wall-clock, locator (`document_path`, `library_path`, `source_document`) and verification-outcome fields with `drop_in_design_view`; never strip by key name. A design field added after IRs were saved (`PCBDesign.silkscreen`, `ManufacturingConstraints.min_silk_text_height_mm` / `min_silk_line_width_mm`) is left out of the design view only while empty (`drop_empty_in_design_view`), so every older IR keeps its hash.
2. A compiler never emits a symbol/footprint it did not find on disk in a KiCad library (`ai_eda.tools.kicad.library`). Pin numbers / pad geometry come from the library file, never from model memory. Mismatch between IR pins and library pins is an error, not a guess.
3. `ValidationStatus` is never boolean. No evidence → `NOT_VERIFIED`, never `PASS`. ERC/DRC results are produced only by `ai_eda/tools/kicad/cli.py`. `mfg.capability` is produced only by `ai_eda.tools.manufacturing.capability.check_capability` and can PASS only on DRC evidence that read the fresh `.kicad_pro` on a kicad-cli version in `PROJECT_RULES_MEASURED_VERSIONS` (empty until measured, so it cannot PASS anywhere yet); fab limits enter the IR only through `--fab-capability` grounding (`ai_eda/tools/manufacturing/capability_file.py`) or the user. `component.fit` and `domain.power.thermal` judge only at a fresh SPICE operating point and answer `NOT_VERIFIED` with the reason for everything they cannot judge (never a proxy verdict); the thermal check applies to every design — no component with a thermal key means `NOT_VERIFIED` naming the keys in the POWER domain and `NOT_APPLICABLE` elsewhere.
4. Agents return `IRProposal`s; only `Orchestrator.apply_proposals` mutates design content, and it validates every payload against the target field's type (`ir.artifacts` / `ir.validation` bookkeeping is written by the stage runners). A required question stops the pipeline even when a FAIL in the same stage outranks it. The pipeline has 19 stages (`STAGE_ORDER` in `ai_eda/workflow/stages.py`): PLACEMENT (`PCBAgent`, deterministic placement - `placement.core_ring` when a part has at least 32 pads, `placement.grid` otherwise - then `routing.maze` 0.2 routing at the rules the finest pad pitch selects (`RoutingParams.for_board`: below 1.0 mm the fine rules), then `silkscreen.place` silkscreen (references beside their courtyards, on F.Fab when no spot is free; connector pin labels; the ASCII project name as title; keep-outs are pad copper, the board edge, the footprints' own silk and earlier texts - not tracks, not the tented vias), all in one `pcb` proposal, never PASS — a proposal is not evidence; the router negotiates congestion (PathFinder-style rip-up and reroute: other nets' clearance halos are a present + history cost, not an obstacle, until no cell is shared or `max_iterations`; every negotiation number is a `RoutingParams` field in each track's `params:` provenance, the note names the iteration count) and emits only whole, mutually legal nets - a net without a legal route gets no copper at all, never half a net; `--answer pcb.placement=skip` skips the stage, `--answer pcb.routing=skip` leaves the placement without copper, `--answer pcb.silkscreen=skip` proposes no silkscreen; by default a net the router cannot route means placement only (a `not applied:` note reports what it did connect), and only the opt-in `--answer pcb.routing=partial` applies the routed nets, each whole, naming every unrouted net for manual routing in KiCad (`pcb.routing.connectivity` then FAILs naming them); existing copper and existing silkscreen are never replaced; `pcb.routing.connectivity` / `pcb.routing.clearance` and `pcb.silk.clearance` / `pcb.silk.overlap` / `pcb.silk.size` in `ai_eda/validation/layout.py` are IR geometry checks, never DRC - the silk text boxes are a documented estimate, not KiCad's font metrics) and FAB_CAPABILITY (`FabCapabilityAgent`, grounded fab limits merged into `pcb.manufacturing`) sit between COMPONENT_SELECTION and IR_BUILD, so validators stamp the placed IR. `CircuitDesignAgent` proposes only from deterministic templates (`divider`, `led`, `rc_lowpass`, `astable`, `atmega128_devboard`) on confirmed requirement values and applies nothing on the run that first shows the `confirm_design` table: a template's free choices become `user_requirement` only through `--answer confirm_design=yes` on a later run whose answers cannot change the inputs (no non-control answer, no `confirm_requirements` / `accept_implicit` / `reject_implicit`) and whose table hash equals the one recorded when it was shown (`ir.requirements.presented`, bookkeeping outside the design hash). `design.inputs_vs_requirements` is an unstamped agent result. Every control key (`confirm_design`, `pcb.placement`, ...) lives in one `CONTROL_KEYS` in `ai_eda/agents/keys.py`; a control answer is never a requirement or a regulatory scope answer.
5. Repairs only regenerate artifacts from the IR or re-run tools. Design changes need a human.
6. Outward-facing actions go through `ai_eda.security.require_approval` (`PAID_API_CALL`: the `--llm-budget-*` flags are the approval of per-call model charges; `SUBSCRIPTION_USE`: `--llm claude` is the approval of calling the model through the user's own Claude Code CLI login - no per-call charge, no budget required, but the run shows the tokens and the CLI's API-equivalent estimate; `NETWORK_FETCH`: `--online`; `SECRET_ACCESS`: `doctor --online`).

## Conventions
- Python 3.12, pydantic v2, `from __future__ import annotations`, type hints everywhere, small modules, docstrings that state the invariant the module enforces.
- Tests in `tests/`; tests that need `kicad-cli` use `pytest.mark.skipif(not KicadCli().available(), ...)` and must otherwise run against the real binary.
- Tool-backed `ValidationResult`s set `tool`, `tool_version`, `artifact_hash`, and attach `Evidence` (report path + hash). A validator that judges by the SPICE operating point reads it only through `ai_eda.tools.spice.evidence.fresh_spice_run` (never `ir.artifacts` directly) and keeps every derived number in `details`, never in the IR.
- `<workdir>/pipeline.json` (written by `ai-eda run`, read by `ai-eda report` / `serve` / `gui`) is a run log like `ir.validation`: never registered as an artifact, never hashed; the report is English, computes no status and never saves the IR; `serve` and `gui` bind 127.0.0.1 only (no `--host`; a `Host` header naming another machine is 421) and are not `ExternalAction`s. `gui` (`ai_eda/gui/`, `ai-eda gui [--root DIR] [--port N] [--open]`, Korean page) is a view and a launcher: every status it shows is copied through `build_report_data`, it registers no artifact, hashes nothing, never edits ir.json itself and never deletes or renames anything (deleting would be `SYSTEM_DELETE`); its only own writes are a new project folder (`cli.new_project`, the code of `ai-eda new`) and the run logs `<workdir>/gui/runs/NNN-<kind>.log`. One run per workdir (409): on POSIX a `flock` on the run log, inherited by the child as its stdout, also holds the slot across GUI processes (per-process on Windows). An existing folder opens under any name that is one safe path component (the ASCII name rule is for `create` only); every previewed file carries its artifact row's facts (design hash, disk), and report labels are shown in Korean through `gui/labels.py` (keyed by the `report.data` constants). Every run is a subprocess `python -P -m ai_eda.cli run|review|stage-reports <ir.json> ...` (cwd = the workdir; `-P` keeps it off `sys.path`, so a project folder never supplies code) whose flags only `cli.run_option_flags()` builds from the form (fields = `RUN_OPTIONS` dests, answers one `--answer` item each, never a shell), so keys, budgets, `--llm claude` and `--online` are approved exactly as on the command line and the GUI adds no flag the user did not set nor reads a key. A POST needs the page's own `Origin` (or none) and `application/json`; files are served only from inside the project workdir (`gui.preview.confined_file`); the page loads only its own `/static/app.js` / `/static/app.css` under `APP_CSP` (`default-src 'self'`, no inline script or style - keep it that way: listeners in app.js, states as app.css classes, text through text nodes); tests never run the real `claude` and the browser tests are `@pytest.mark.browser`. The 기판 tab toggles the board figure's `silk` group; the 3D tab is a hand-written WebGL viewer in app.js (no library, `APP_CSP` unchanged) of `/preview/<name>/board.glb` (`model/gltf-binary`: the scene of the current IR, the same function the `MODEL_3D` compiler writes, so an unchanged IR gives the registered file's bytes), with the server's isometric SVG (`/preview/<name>/board3d/<view>.svg`) where WebGL is missing, and KiCad's own STEP / GLB / render files only linked when a kicad-cli run registered them.
- The four Korean stage reports (`ai_eda/report/stages.py`: `01_이론_보고서.md` after ARCHITECTURE once the design exists, `02_부품선정_보고서.md` after COMPONENT_SELECTION, `03_회로_보고서.md` after PCB, `04_최종_보고서.md` after RELEASE, each also as `.html` - the Markdown rendered by `ai_eda/report/pdf.py` with the deterministic inline SVG figures of `ai_eda/report/figures.py` (theory: the template's `theory_figures(ir)` curves + the measured waveform read only through `fresh_spice_run`; circuit: placement, routed board from the KiCad library with its silkscreen, per-net copper bars, the isometric 3D preview of the scene the `MODEL_3D` artifact is written from - the text also gives the silk rules with the placer's recorded values and copies the latest `pcb.silk.*`; final: the tolerance chart + the waveform; parts: none) - and as `.pdf` when `find_browser()` finds a headless Chromium / Chrome / Edge (none found means `.md` + `.html` and the printed reason, never a failure; a figure whose data is missing is one Korean sentence; the Markdown keeps a `![fig](fig:<id>)` placeholder + italic caption per figure); `ai-eda run` writes them through `Orchestrator.run(after_stage=...)` and re-writes all four after RELEASE, `ai-eda stage-reports [--no-pdf] [--browser PATH]` re-writes them from ir.json + pipeline.json) are views under the same rule as `report.html`: every status is copied, none computed, nothing saved, no artifact; they carry no wall-clock and no absolute path (files by basename, libraries by lib id; `strip_paths` cuts paths out of quoted messages), so the same IR + record is byte-identical. Numbers come from `ir.parameters` (the calculator notes are the formulas), `ir.validation`, the run record, the library on disk, the templates' `theory()` / `part_notes()` and the named reference formulas (IPC-2221 current capacity and 6-1 B2 spacing, copper resistance) - a value the IR lacks prints `기록 없음`, a substitute part name always carries `(검증되지 않음: ...)`. A builder that raises is printed on stderr by the CLI and never aborts the run. No LLM anywhere; the HTML report stays English.
- Template part values (`Component.value`) are display text: KiCad style, SI prefix, no unit, at most 5 significant digits, trailing zeros dropped (`100n`, `1.5915k`, `M` = mega; `ai_eda/tools/calc/part_value.py`, `TEMPLATE_VERSION` 0.2). The SPICE binding keeps the calculator's exact number and the netlist spells it with `format_spice_number` (`1e-7`); compare a part value with a design value only through `part_value_agrees` (the quantity parser, within the display rounding; an overflowing text is no number, `None`), never as strings, and never feed a part value to the SPICE parser (it reads `M` as milli). A project confirmed under template v0.1 keeps its netlist-spelled values and its design hash (a confirmed design is never rebuilt), so report text claims the 5-digit spelling only where `display_spelled` says the IR carries it.
- BOM free-text cells (`Value` / `Description`) are neutralised with a leading apostrophe by `ai_eda/tools/manufacturing/csv_cells.py` (`free_text_cell`, decoded only by `bom_cell_text`); identity / sourcing cells and CPL designators are refused instead. Whether spreadsheets show the apostrophe literally is not measured here.
